# CORTHEX-MEMORY: 도메인

[English](memory.md)

CORTHEX 자신의 프로젝트에서 `corthex-memory` 플러그인의 01단계입니다. 상태: 2026-10-24에 썼습니다. 관리자가 같은 날 이 파일을 바탕으로 한 요구사항(02단계)을 확인했고, 뒤 단계에서 바뀌는 것은 날짜와 함께 여기에 더합니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다. 2026-11-03에 C2의 줄 편집·줄 기록, 충돌 후보, 실행 기록·되돌리기를 승인해 TERM-014·017을 고치고 TERM-135~138을 더했습니다.

CORTHEX-MEMORY의 맥락과 용어집을 한 파일에 둡니다. 프로젝트의 다른 부분은 이 폴더에 따로 파일을 두며, 그 옆의 번역은 원본으로 읽지 않습니다.

읽은 자료:

- 관리자 기록에 있는 CORTHEX-MEMORY 설계 초안(2026-10-23)과 그 문제 목록, 2026-10-23 훅 시험.
- 2026-10-24 Windows 훅 시험, [`.github/workflows/windows-hook-check.yml`](../../.github/workflows/windows-hook-check.yml).
- [`plugins/corthex-memory/`](../../plugins/corthex-memory/)의 세션 시작 훅과 [docs/architecture.ko.md](../architecture.ko.md#세션-시작-문맥)의 설명.
- 비용 상한을 두지 않는다는 관리자 결정(2026-10-24).

## 맥락

### CTX-001 기록

목적: 켠 프로젝트의 세션에서 오간 말을 세션을 늦추지 않고 기기의 원문 기록에 적습니다.

- 사건: 세션 시작됨, 프롬프트 보냄, 턴 끝남, 세션 끝남, 턴 기록됨, 기록 건너뜀
- 명령: 턴 기록하기
- 정책: 켠 프로젝트에서만 적습니다. 세션의 프로젝트는 저장소 안의 설정이 아니라 기기의 프로젝트 목록으로 정합니다. 무엇이든 쓰기 전에 비밀값과 비공개 구간을 지웁니다. 프롬프트와 최종 답변을 적고, 도구 호출과 그 결과는 적지 않습니다. 세션을 막거나 실패시키지 않으며, 기록에 실패하면 그대로 진행하고 적어 둡니다.
- 행위자: 사용자, 에이전트, 도구
- 열린 질문: 도구가 문맥을 압축하며 만든 요약도 적을까요? 하위 에이전트의 턴도 그 세션의 턴으로 셀까요?

### CTX-002 정리

목적: 새 원문 턴을 뒤에서 프로젝트의 현재 상태와 기억 항목으로 바꾸고, 출처를 함께 둡니다.

- 사건: 정리할 때가 됨, 정리 시작됨, 항목 더해짐, 항목 대체됨, 항목 철회됨, 현재 상태 고쳐짐, 정리 실패함, 정리 멈춤, 통합 끝남
- 명령: 프로젝트 정리하기, 프로젝트 통합하기, 인용 확인하기
- 정책: 프로젝트마다 정리는 한 번에 하나만 돕니다. 항목은 인용이 원문 기록에 글자 그대로 있을 때만 저장합니다. 사용자 결정은 사용자 자신의 말로만 만듭니다. 항목은 대체나 철회로 표시하고, 몰래 고쳐 쓰지 않습니다. 모델 요청이 실패하면 그 원문 턴은 다음 정리를 기다립니다. 같은 턴에서 실패가 되풀이되면 사용자가 다시 시작할 때까지 정리를 멈춥니다. 비용 때문에 정리를 멈추지 않습니다.
- 행위자: 정리 프로세스, Anthropic API
- 2026-10-27에 답한 질문: 04단계의 답 1에서 SPEC-010을 확인했습니다. 턴이 끝날 때 정리 전 턴 10개나 30분보다 오래된 턴 중 먼저 오는 조건, 세션이 끝날 때 정리 전 턴 하나 이상, 세션이 시작될 때 이전 세션에서 남은 턴이 정리 조건입니다.

### CTX-003 불러오기

목적: 세션을 시작할 때와 프롬프트마다 에이전트에게 필요한 기억만 줍니다.

- 사건: 시작 요약 넣음, 항목 불러옴, 불러온 것 없음, 불러오기 시간 초과
- 명령: 시작 요약 만들기, 프롬프트에 맞게 불러오기, 기억 찾기
- 정책: 세션의 프로젝트 것만. 현재 항목만. 넣는 기준점을 넘는 항목이 없으면 아무것도 넣지 않습니다. 넣는 기억에는 지시가 아니라 참고 자료라고 표시합니다. 크기 상한을 지킵니다. 불러오기가 늦거나 API가 실패하면 아무것도 넣지 않습니다. 저장소 파일에서 온 글은 정해진 형식으로만 보여 줍니다.
- 행위자: 도구, 에이전트, OpenAI API
- 2026-10-27에 답한 질문: [요구사항](../02-prd/memory.ko.md#지금-유효한-결정)의 D2대로 임베딩과 규칙으로 프롬프트별 항목을 고르며, Claude Haiku 5.5는 백그라운드 정리에만 씁니다.

### CTX-004 동기화

목적: 사용자의 여러 기기가 정리된 층을 함께 씁니다.

- 사건: 올림, 받음, 합침, 지운 기록 적용됨
- 명령: 기억 동기화하기
- 정책: 사용자가 켜기 전에는 꺼져 있습니다. 정리된 층만 사용자의 비공개 동기화 저장소로 가고, 원문 기록과 검색 색인은 각 기기에 남습니다. 잊은 항목은 동기화로 되살아나지 않습니다.
- 행위자: 사용자, 다른 기기, 동기화 저장소
- 2026-10-27에 답한 질문: 정리된 층은 [요구사항](../02-prd/memory.ko.md#지금-유효한-결정)의 D3대로 사용자가 운영하는 HTTPS 창구와 Postgres·pgvector 서버를 통해 함께 씁니다. 기기에서 데이터베이스에 직접 붙지 않습니다.

### CTX-005 관리

목적: 무엇을 기억하고, 어디로 보내고, 비용을 어떻게 낼지 사용자가 정하고, 그것을 보고 되돌릴 수 있게 합니다.

- 사건: 프로젝트 켜짐, 프로젝트 꺼짐, 동의함, 항목 고정함, 항목 고정 풂, 항목 잊음, 기억 폴더 모두 지움, 사용량 기록됨
- 명령: 프로젝트 켜기, 프로젝트 끄기, 항목 고정하기, 고정 풀기, 항목 잊기, 모두 지우기, 상태 보기
- 정책: 프로젝트는 꺼진 채로 시작합니다. 동의 전에는 어떤 API에도 보내지 않습니다. 키는 기억 전용 키 변수나 도구의 보안 저장소에서만 읽고, 어디에도 쓰지 않습니다. 모델 호출마다 사용량을 기록합니다. 비용 상한은 두지 않습니다(2026-10-24 관리자 결정). 한도를 원하는 사용자는 모델 제공사의 콘솔에서 정합니다. 플러그인을 지워도 기억 폴더는 남습니다.
- 행위자: 사용자
- 2026-10-27에 답한 질문: [요구사항](../02-prd/memory.ko.md#지금-유효한-결정)의 D4대로 기억 전용 키 두 개를 씁니다. Anthropic 키는 관리자의 구독에 연결된 Console 조직에서 만들어 월 API 크레딧으로 정리 비용을 내고, OpenAI 키는 임베딩용으로 따로 둡니다.
