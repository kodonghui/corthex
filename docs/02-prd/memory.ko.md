# CORTHEX-MEMORY: 요구사항

[English](memory.md)

CORTHEX 자신의 프로젝트에서 `corthex-memory` 플러그인의 02단계입니다. 상태: 관리자가 2026-10-24에 범위를 고칠 것 없이 확인했습니다(이 단계의 첫 확인 지점). 2026-10-27에 D1·D2·D4와 뒤 단계의 추천을 승인했고, D3는 아래의 새 서버 동기화 안으로 정했습니다. 원문 보관 기본값은 100일입니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다. 2026-11-03에 C2 추가 세 가지를 승인해 REQ-037·054를 넓히고 REQ-219~225를 더했습니다.

입력: [docs/01-domain/memory.ko.md](../01-domain/memory.ko.md)의 맥락과 용어집(CTX-001\~CTX-005, TERM-001\~TERM-046). 이 파일의 말은 거기서 정한 뜻으로 씁니다.

## 목표

사용자의 작업 문맥이 세션, 기기, 두 도구 사이에서 이어지게 합니다. 사용자가 다시 설명하지 않아도, 메인 모델의 한도를 쓰지 않아도, 에이전트는 세션을 시작할 때와 프롬프트마다 프로젝트의 현재 상태와 중요한 결정을 알고 일합니다.

## 문제

관리자 기록에는 오래 이어지는 AI 작업의 문제가 이렇게 적혀 있습니다. 아래 요구사항은 저마다 어느 문제나 결정에서 왔는지 적습니다.

1. 긴 세션에서는 앞의 문맥이 흐려지고, 프롬프트마다 그에 맞는 기억이 필요합니다.
2. 새 세션, 다른 기기, 다른 도구에서는 문맥을 다시 갖추고 설명해야 해서 시간과 사용 한도가 듭니다.
3. 여러 프로젝트의 문맥이 섞입니다.
4. Notion, Jira, Git의 기록을 거듭 다시 읽느라 큰 모델의 한도를 씁니다.
5. 요약하면 세부가 빠지고, 철회한 결정이 되살아나고, 누가 무엇을 말했는지 흐려집니다.
6. 세션이 끊기면 그 세션에서 한 말을 잃습니다.

## 범위

이번 릴리스는 설계 초안의 M1 계획을 세 걸음으로 만듭니다: C1 기록과 시작 요약, C2 정리와 불러오기, C3 기기 간 동기화.

- 포함: 기록, 정리, 시작 요약, 프롬프트마다 불러오기, 찾기, 잊기, 상태, 모두 지우기, 사용자가 운영하는 HTTPS 창구와 서버를 통한 선택적 동기화, 사용량 기록.
- 제외: 페이지 같은 화면, 여러 사람이 함께 쓰는 기억, 도구 호출과 그 결과의 기록, 기기의 데이터베이스 직접 접속, 프로젝트 목록에 없는 폴더.
- 정답키나 학생 기록처럼 보호할 자료가 있는 프로젝트는 첫 시범에서 켜지 않습니다.

기억의 결정 가운데 열린 것은 없습니다. 2026-10-27에 D1~D4의 답을 받았습니다. D1·D2·D4는 추천대로 정했고 D3는 새 안을 선택했으며, 아래 표는 질문과 검토한 다른 선택을 보존합니다.
