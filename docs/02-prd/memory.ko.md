# CORTHEX-MEMORY: 요구사항

[English](memory.md)

CORTHEX 자신의 프로젝트에서 `corthex-memory` 플러그인의 02단계입니다. 상태: 2026-10-24 초안이며, 관리자의 범위 확인(이 단계의 첫 확인 지점)을 기다립니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다.

입력: [docs/01-domain/memory.ko.md](../01-domain/memory.ko.md)의 맥락과 용어집(CTX-001~CTX-005, TERM-001~TERM-046). 이 파일의 말은 거기서 정한 뜻으로 씁니다.

## 목표

사용자의 작업 문맥이 세션, 기기, 두 도구 사이에서 이어지게 합니다. 사용자가 다시 설명하지 않아도, 메인 모델의 한도를 쓰지 않아도, 에이전트는 세션을 시작할 때와 프롬프트마다 프로젝트의 현재 상태와 중요한 결정을 알고 일합니다.

## 문제

관리자 기록에는 오래 이어지는 AI 작업의 문제가 이렇게 적혀 있습니다. 아래 요구사항은 저마다 어느 문제나 결정에서 왔는지 적습니다.

1. 긴 세션에서는 앞의 문맥이 흐려지고, 프롬프트마다 그에 맞는 기억이 필요합니다.
2. 새 세션, 다른 기기, 다른 도구에서는 문맥을 다시 갖추고 설명해야 해서 시간과 사용 한도가 듭니다.
3. 여러 프로젝트의 문맥이 섞입니다.
4. Notion, Jira, Git의 기록을 거듭 다시 읽느라 큰 모델의 한도를 씁니다.
5. 요약하면 세부가 빠지고, 철회한 결정이 되살아나고, 누가 무엇을 말했는지 흐려집니다.
6. 세션이 끊기면 그 세션에서 한 말을 잃습니다.

## 범위

이번 릴리스는 설계 초안의 M1 계획을 세 걸음으로 만듭니다: C1 기록과 시작 요약, C2 정리와 불러오기, C3 기기 간 동기화.

- 포함: 기록, 정리, 시작 요약, 프롬프트마다 불러오기, 찾기, 잊기, 상태, 모두 지우기, 비공개 Git 저장소를 통한 선택적 동기화, 사용량 기록.
- 제외: 페이지 같은 화면, 여러 사람이 함께 쓰는 기억, 도구 호출과 그 결과의 기록, 동기화 저장소로서의 NEXUS나 Postgres(나중에 결정 D3로 정함), 프로젝트 목록에 없는 폴더.
- 정답키나 학생 기록처럼 보호할 자료가 있는 프로젝트는 첫 시범에서 켜지 않습니다.

이 파일은 D1을 추천안대로 가정합니다. 상태가 `open`인 요구사항은 적힌 결정에 달려 있습니다.

| ID | 질문 | 추천 | 다른 선택 |
| --- | --- | --- | --- |
| D1 | 기억을 어떻게 만들까 | M1: 이 파일의 계획대로 `corthex-memory`를 만듭니다 | 이미 있는 기억 플러그인을 씁니다(모델을 스스로 고르고 로컬 서버를 돌림). NEXUS를 먼저 만듭니다(서버가 있어야 기억이 동작함). 도구 자체의 기억에 맡깁니다(도구나 기기를 넘나들지 못함) |
| D2 | 프롬프트마다 항목을 어떻게 고를까 | 임베딩과 규칙으로 고르고, Claude Haiku 5.5는 뒤에서만 일합니다 | 프롬프트마다 xhigh 강도의 Haiku 5.5가 고릅니다(프롬프트마다 더 느리고 비쌈, 잰 값이 아닌 추정). 프롬프트마다 불러오지 않습니다(시작 요약과 찾기만) |
| D3 | 기기끼리 기억을 어떻게 함께 쓸까 | 사용자의 비공개 Git 저장소. 다른 사용자에게는 기본으로 꺼 둡니다 | NEXUS가 동기화할 수 있을 때까지 기기마다 따로 둡니다. 함께 쓰지 않습니다. 모든 기기가 Postgres 데이터베이스 하나를 씁니다(대화에서 나온 기억을 외부 데이터베이스에 두고, 모든 기기에 그 비밀값이 필요함) |
| D4 | 모델 호출 비용을 어떻게 낼까 | 기억 전용 키 두 개(Anthropic용, OpenAI용). Anthropic 키는 관리자의 구독에 연결된 Console 조직에서 만들어, 월간 API 크레딧으로 정리 비용을 냅니다 | 구독 로그인으로 `claude -p`를 써서 정리합니다(API 크레딧이 아니라 요금제 한도를 쓰고, 플러그인 자신의 훅을 막는 장치가 필요하며, Codex만 쓰는 사용자는 쓸 수 없음) |
