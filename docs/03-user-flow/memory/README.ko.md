# CORTHEX-MEMORY: 사용자 흐름

[English](README.md)

CORTHEX 자신의 프로젝트에서 `corthex-memory` 플러그인의 03단계입니다. 상태: 2026-10-24 초안입니다. 2026-10-24에 설계 깊이를 고를 때 정한 대로, 관리자는 이 흐름을 기능 명세(04단계)와 함께 확인합니다. 이곳의 파일과 그 한국어 번역이 다르면 영어 파일이 원본입니다.

입력: [docs/02-prd/memory.ko.md](../../02-prd/memory.ko.md)의 요구사항(REQ-001\~REQ-065)과 [docs/01-domain/memory.ko.md](../../01-domain/memory.ko.md)의 맥락과 용어집. 이곳의 말은 거기서 정한 뜻으로 씁니다. 흐름은 결정 D1\~D4의 추천을 가정하며, FL-004는 D2에, FL-012는 D3에 달려 있습니다.

흐름마다 파일 하나에 Mermaid 흐름도가 있고, 단계마다 그 단계가 다루는 요구사항을 적습니다. FL-005는 첫 그림을 읽기 쉽게 두려고, 제안된 변경 하나를 적용하는 과정을 두 번째 그림으로 나눠 그립니다.

## 흐름이 도는 때

| 때 | 흐름 |
| --- | --- |
| 세션이 시작되거나, 이어 열리거나, 갈라지거나, 비워지거나, 압축될 때 | FL-003, 그리고 거기서 시작될 수 있는 FL-006 |
| 사용자가 프롬프트를 보낼 때 | FL-002, 이어서 FL-004 |
| 턴이 끝날 때 | FL-002의 끝부분 |
| 세션이 끝날 때 | 원문 기록의 세션 경계. FL-003에서 시작할 때와 같은 단계(REQ-003) |
| 사용자가 묻고 에이전트가 기억 스킬을 따를 때 | FL-001, FL-007\~FL-011 |
| 위의 때 가운데 하나에서 시작해 뒤에서 | FL-005, FL-006, FL-012 |

어느 도구의 어느 훅이 어느 단계를 돌릴지는 06단계가 정합니다. 2026-10-23의 훅 시험에서는 두 도구 모두 세션 시작 훅과 프롬프트 훅이 도는 것을 보았고, 턴 끝 훅은 아직 도는 것을 보지 못했습니다. 그래서 FL-002의 끝부분은 12단계에서 시험하기 전까지 도구의 문서에 기댑니다.

## 어느 흐름에도 쓰이지 않는 요구사항

REQ-060(Linux, macOS, Windows), REQ-061(Python 3.8과 그 표준 라이브러리), REQ-062(루트 `plugin.json` 없음), REQ-063(기억 폴더의 형식 버전)은 흐름 하나가 아니라 플러그인 전체에 걸립니다. 기능 명세가 이것을 적고, QA가 확인합니다. 나머지 요구사항은 모두 흐름 하나 이상에 나옵니다.

## 기능 명세에서 정할 것

흐름을 그리며, 요구사항이 열어 둔 다음 질문이 나왔습니다.

1. 정리 조건: 턴 몇 개 뒤, 몇 분 뒤, 세션이 끝날 때 가운데 무엇으로 할지(CTX-002의 열린 질문). FL-005는 어느 쪽에서든 시작합니다.
2. 사라지는 기기: 클라우드 세션은 끝나면 파일이 사라지는 컨테이너에서 돌기 때문에, 끝나기 전에 정리와 동기화가 돌지 않으면 원문 기록과 아직 정리하지 않은 턴을 잃습니다(REQ-008, REQ-012).
3. 한 프로젝트의 두 세션이 동시에 돌 때: 덧붙이기가 원문 기록을 깨뜨리지 않아야 하고(REQ-064), 둘 가운데 하나만 정리합니다(REQ-021).
4. 키가 없을 때: FL-003은 정리가 키를 기다린다고 시작 요약에 알리는데, REQ-029는 정리가 실패하거나 멈춘 경우만 적습니다.
5. 항목 철회: FL-005는 그 항목을 말한 사람이 철회할 때만 철회됨으로 표시합니다(REQ-020, TERM-017). 에이전트가 한 말을 사용자가 바로잡을 때 어떻게 할지는 명세가 정합니다.
6. 지운 기록은 다른 기기가 잊은 항목과 그 항목이 인용한 원문의 글을 찾을 수 있게 하되, 그 글 자체는 담지 않아야 합니다(REQ-045, REQ-054).
7. 여러 항목이 함께 쓰는 인용: 한 항목을 잊어도, 같은 원문의 글을 인용한 다른 항목의 출처가 깨지지 않아야 합니다(REQ-017, REQ-054).
8. 보관 기간과 멈춘 정리: 고장 멈춤이 정리를 멈춘 동안처럼, 아직 정리하지 않은 원문 턴이 30일 보관 기간에 닿을 수 있습니다(REQ-009, REQ-024).
9. 한 프로젝트의 기억만 지우기: 요구사항은 프로젝트를 끄는 것(REQ-058)과 기억 폴더 전체를 지우는 것(REQ-055)만 다룹니다.
10. 크기: 요청 하나에 들어가지 않는 턴 하나(REQ-022), 그리고 요청 하나에 담기는 것보다 항목이 많은 통합.
11. 고정 항목이 대체되거나 철회되면 시작 요약에서 빠집니다(REQ-037). 고정을 새 항목으로 옮길까요?
12. 훅 시간: 성공 기준은 속도를 기억 상태에서 읽는데, REQ-053은 그것을 적지 않습니다.
13. 동기화 켜기: 사용자가 동기화 저장소를 어떻게 고르고, 플러그인이 그것이 비공개인지 어떻게 확인할지(REQ-042).
