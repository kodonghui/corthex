# CORTHEX-MEMORY: 기능 명세

[English](memory.md)

CORTHEX 자신의 프로젝트에서 `corthex-memory` 플러그인의 04단계입니다. 상태: 2026-10-27 확인했습니다. 남겨 둔 Git 동기화 설계는 D3로 대체됐습니다. 관리자는 이 파일을 03단계의 사용자 흐름과 함께 확인합니다. 확인이 끝나면 이번 출시의 행을 고정하며, 그 뒤에 행을 바꾸려면 관리자의 결정이 필요합니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다. 2026-11-03에 C2 추가 세 가지를 승인해 SPEC-009·012·015·016·017·019·021·022·023·025·033·034·035를 고치고 SPEC-143~145를 더했습니다. 2026-11-07에는 압축에 관한 추가 여섯 가지를 승인해 SPEC-008·017·019·021·024·025를 고치고 SPEC-146~148을 더했습니다.

입력: [docs/02-prd/memory.ko.md](../02-prd/memory.ko.md)의 요구사항(REQ-001\~REQ-065 및 REQ-194\~REQ-196, REQ-219\~REQ-229), [docs/03-user-flow/memory/](../03-user-flow/memory/README.ko.md)의 사용자 흐름(FL-001\~FL-012, FL-117), [docs/01-domain/memory.ko.md](../01-domain/memory.ko.md)의 용어집. 이 파일의 말은 거기서 정한 뜻으로 씁니다. 이 단계에서 용어집에 새 용어 열한 개를 더했습니다([새 용어](#새-용어) 참고). 2026-10-27에 D1·D2·D4와 요구사항 변경 일곱 개를 확인했고, D3는 02단계의 HTTPS 창구와 서버 안으로 정했습니다. 남겨 둔 Git 동기화 상세의 상태는 `superseded (D3, 2026-10-27)`이며 C3 전에 대체 설계가 필요합니다.

> D3 설계 상태: `superseded (D3, 2026-10-27)`. 이곳에 남겨 둔 Git 동기화 제안은 2026-10-27에 확인한 D3 결정으로 대체됐습니다. 구현하거나 실행할 계획이 아닌 과거 자료입니다. HTTPS 창구와 서버 동기화 설계는 C3 전에 따로 작성합니다. 기기의 저장소는 파일과 SQLite 검색 색인을 유지합니다. 이 표시는 여러 단계가 공유하는 행·설정·예시의 동기화 부분에도 적용하며, 그 C1/C2 부분은 확인된 상태입니다.

## 이 파일을 읽는 법

- 행 하나가 기억 플러그인의 동작 하나입니다. `근거` 열에 그 행이 맡는 요구사항과 흐름을 적습니다. 기능 Must 요구사항은 모두 행이 하나 이상 있습니다.
- 상태: 확인한 동작은 `active`, 남겨 둔 Git 동기화 행은 `superseded (D3, 2026-10-27)`입니다. 요구사항 변경 일곱 개는 승인됐습니다([요구사항이 묻지 않은 동작](#요구사항이-묻지-않은-동작) 참고).
- 100,000토큰이나 8,000바이트처럼 요구사항에서 온 숫자는 상한입니다. 정리 시작 조건, 보관 기간, 넣는 기준점, 8글자 건너뛰기는 기억 설정의 기본값입니다. 마감 시간 같은 나머지 숫자는 코드에 고정하며, 시험 운영 결과에 따라 다음 판에서 바꿀 수 있습니다.
- "훅"은 기억 플러그인의 훅 스크립트입니다. 도구마다 어느 훅 사건이 그것을 돌리는지는 06단계가 정합니다. "뒤에서"는 SPEC-013의 따로 떨어진 프로세스를 말합니다.
- 비기능 요구사항은 그것을 적은 행으로 맞추고 QA(12단계)에서 시험합니다. [플러그인 전체](#플러그인-전체)에 모아 둡니다.

| 4. 키가 없을 때 | 정리나 불러오기가 동의나 기억 전용 키를 기다리면 시작 요약이 알리고, 어느 키를 어디에 둘지 말합니다. 2026-10-27에 REQ-029로 확인했습니다. | SPEC-022 |

| 9. 한 프로젝트의 기억만 지우기 | 동기화가 켜지면 프로젝트 지운 기록을 남기는 동작을 포함해 REQ-194로 확인했습니다. | SPEC-037 |
| 10. 크기 | 요청 하나에는 입력 100,000토큰까지 턴을 통째로 담고, 크면 토큰 세기 API로 셉니다. 요청 하나에 들어가지 않는 턴은 나눠 보내고, 통합은 종류별로, 그다음 시간순으로 묶어 보냅니다. 요청에서 제 몫보다 긴 항목 목록은 짧은 줄로, 그래도 길면 요청에 가장 필요한 항목부터 일부만 보냅니다. | SPEC-015, SPEC-019 |
| 11. 고정 항목이 대체되거나 철회될 때 | 고정은 그 항목을 대체한 항목으로 옮깁니다. 철회되거나 잊은 항목은 고정이 풀립니다. 다음 시작 요약이 한 번 알립니다. | SPEC-034 |

## 압축 추가 (CTX-002, CTX-003)

호스트는 긴 세션을 자기 요약으로 압축합니다. 이 행들은 그 요약이 중요한 것을 지키도록 돕고, 지키지 못했으면 에이전트에게 알립니다. 요약을 기록하거나 보내지는 않습니다(SPEC-003). 압축 훅에 필요한 것을 주는 호스트는 Claude Code뿐이므로, Codex에서는 이 훅들이 아무것도 하지 않습니다(06단계).

| 항목 | 내용 |
| --- | --- |
| 입력 | 임베딩 모델의 입력 한도(`text-embedding-3-small`은 8,192토큰)에 맞게 자른, 지우기 처리한 프롬프트와, 06단계가 정하는 줄인 벡터 길이. |
| 보내지 않는 것 | 최종 답변, 다른 턴, 항목, 키, 프로젝트의 이름이나 폴더. |
| 출력 | 벡터 하나. |
| 서버가 확인할 것 | 벡터가 요청한 길이이고, 플러그인은 점수를 매기기 전에 길이를 1로 맞춥니다. |
| 실패 | 800ms보다 늦거나 오류 → 아무것도 넣지 않고, 실패 기록에 남기며, 프롬프트는 이어집니다(REQ-035). 사용자는 기억 상태에서 그 수를 봅니다. |
| 사람의 결정 | 프롬프트마다는 없습니다. 2026-11-05 위임에 따라 에이전트가 짧은 실제 프롬프트 표본의 넣기 기록을 성공 기준으로 판정하며 에이전트 평가임을 보고서에 적습니다. |

| 항목 | 내용 |

## 확인할 것

2026-10-27 통과: 아래 추천을 승인했고, 원문 보관 기본값 100일과 새 D3 결정은 02단계에 기록했습니다. Git 전용 추천은 대체됐으며 서버 동기화 설계는 C3 전에 따로 작성합니다. 계획과 선택을 확인한 것이며, 출시 여부는 각 시험 운영 뒤에 정합니다.

3. 클라우드 세션의 컨테이너 같은 임시 기기: 그 기억은 동기화로만 남고, 동의는 사용자 자신의 환경 설정으로 옵니다(SPEC-011).
4. D3 추천안에서 이력을 두지 않는 동기화 저장소. 다만 저장소를 맡은 서비스는 바뀐 커밋을 한동안 둘 수 있습니다(SPEC-026, SPEC-028).

### 05단계: 기억 폴더
