# CORTHEX-MEMORY: 작업 분해

[English](memory.md)

CORTHEX 자신의 프로젝트에서 `corthex-memory` 플러그인의 10단계입니다. 상태: 2026-10-27 확인했습니다. 남겨 둔 Git 동기화 설계는 D3로 대체됐습니다. 이 단계에서 확인하는 것은 다음 출시 단계인 C1의 계획입니다: 관리자는 C1을 만들기 전에 이 계획을 기능 명세, 기억 폴더, 인터페이스와 함께 확인하며, 그 확인 전에는 어떤 작업도 시작하지 않습니다. C2와 C3의 작업은 각 출시 단계를 시작하기 전에 다듬고 같은 방법으로 합의합니다. 이 번역과 영어 원문이 다르면 영어 원문이 원본입니다. 2026-11-03 C2 결정의 줄 기록·충돌 후보·실행 되돌리기를 연결하고 TASK-070~072를 더했습니다. 2026-11-07 압축 추가로 TASK-111~116을 더했습니다. C1 완료 상태는 유지합니다. 2026-11-04에 C2 기술 분할·실제 대화 표본을 승인했으며 2026-11-05 결정으로 C2는 에이전트의 짧은 실제 표본 평가를 진행하고 C3 시험 방식은 D3 서버 설계 때 정합니다.

입력: [docs/04-functional-spec/memory.ko.md](../04-functional-spec/memory.ko.md)의 기능 명세(SPEC-001\~SPEC-039, SPEC-143\~SPEC-148), [docs/05-erd/memory.ko.md](../05-erd/memory.ko.md)의 기억 폴더(TBL-001\~TBL-022, TBL-119\~TBL-122), [docs/06-api/memory.ko.md](../06-api/memory.ko.md)의 인터페이스(API-001\~API-032, API-151\~API-156), 특히 그 파일들의 10단계를 위한 메모. 그 메모는 일을 [요구사항](../02-prd/memory.ko.md)의 출시 단계로 나눕니다: C1 기록과 시작 요약, C2 정리와 불러오기, C3 기기 간 동기화. 기억 플러그인에는 화면이 없으므로 어떤 작업도 화면(SCR)을 가리키지 않으며, 대화 안에서 기억 스킬이 하는 답이 화면을 대신합니다. 2026-10-27에 D1·D2·D4와 요구사항 변경 일곱 개를 확인했고, D3는 02단계의 HTTPS 창구와 서버 안으로 정했습니다. 남겨 둔 Git 동기화 상세의 상태는 `superseded (D3, 2026-10-27)`이며 C3 전에 대체 설계가 필요합니다.

> D3 설계 상태: `superseded (D3, 2026-10-27)`. 이곳에 남겨 둔 Git 동기화 제안은 2026-10-27에 확인한 D3 결정으로 대체됐습니다. 구현하거나 실행할 계획이 아닌 과거 자료입니다. HTTPS 창구와 서버 동기화 설계는 C3 전에 따로 작성합니다. 기기의 저장소는 파일과 SQLite 검색 색인을 유지합니다. 이 표시는 여러 단계가 공유하는 행·설정·예시의 동기화 부분에도 적용하며, 그 C1/C2 부분은 확인된 상태입니다.

## 이 파일을 읽는 법

- 작업(TASK) 하나는 담당이 끝낼 수 있고 다른 사람이 따로 확인할 수 있는 일의 한 조각입니다. 풀 리퀘스트(PR) 하나가 서로 기대는 작업 여럿을 끝낼 수 있고, 그러면 그 작업들을 적습니다.
- `근거`: 작업이 만드는 동작(SPEC). 모든 동작에 작업이 있고, 기능 명세의 완료 조건은 모두 그것을 시험하는 작업의 `끝났다고 볼 때`에 적혀 있습니다: `SPEC-005의 완료 조건`은 그 전부를, `SPEC-009의 첫째와 셋째`는 기능 명세에 적힌 차례로 그 일부를 가리킵니다. 어떤 동작의 완료 조건에 뒤의 출시 단계가 필요하면, 그 출시 단계의 작업이 그것을 시험합니다.
- `건드리는 곳`: 작업이 코드를 쓰는 인터페이스(API)와 저장 단위(TBL). 공통 코드와 검사는 `없음`입니다. 모든 인터페이스와 모든 저장 단위를 어떤 작업이 건드립니다.
- `선행 작업`: 먼저 끝나야 하는 작업, 또는 `없음`. 어떤 작업도 뒤의 출시 단계의 작업에 기대지 않고, 기대는 관계에는 고리가 없습니다.
- `담당`: `agent`는 저장소에서 일하며 PR을 여는 AI 에이전트이고, `maintainer`는 관리자의 판단, 기기, 계정이 필요한 일을 맡는 관리자입니다.
- `추정`: 날짜가 아니라 크기입니다. 에이전트의 작업에서 S는 바뀐 코드와 테스트가 300줄쯤까지, M은 800줄쯤까지, L은 2,000줄쯤까지이며, 더 큰 작업은 시작하기 전에 나눕니다. 관리자의 작업에서 S는 관리자의 시간이 30분 안, M은 두 시간까지이고, L은 시험 운영처럼 며칠에 걸칩니다.
- `끝났다고 볼 때`: 다른 사람이 확인하는 것. 따로 적지 않았으면, 테스트가 Python 3.8과 가장 새 Python에서, Linux, macOS, Windows에서 통과합니다(REQ-060, REQ-061). 인터페이스를 건드리는 작업은 결과마다 통과하는 테스트가 있어야 끝납니다. [결과](#결과)는 인터페이스마다 그 결과와 그것을 시험하는 작업을 적습니다. `끝났다고 볼 때`의 한 항목을 훅·명령·기억 상태로만, 또는 그 PR이 돌릴 수 없는 시스템에서만 확인할 수 있으면 나머지가 통과할 때 그 작업은 done입니다. 그 항목은 케이스의 Task 칸 또는 12단계의 '케이스가 도는 곳'이 정한 뒤 작업에서 통과합니다.
- `상태`: `todo`, `in progress`, 끝낸 PR과 함께 `done (#N)`, 또는 나누거나 바꾸어 다른 작업이 대신한 작업이면 `removed (YYYY-MM-DD)`. `superseded (D3, 2026-10-27)`은 남겨 둔 C3 설계 기록이며, 대체 계획을 확인하기 전에는 실행하지 않습니다. 작업의 번호는 바꾸지 않고 행도 지우지 않습니다.

## C1: 기록과 시작 요약

0.2.0 판. 훅이 켠 프로젝트마다 프롬프트, 최종 답변, 세션 경계를 기록합니다. 시작 요약에 기억 부분이 생기며, C2가 정리하기 전까지 그 부분에는 알림과 `Memory holds nothing for this project yet.` 줄만 담깁니다. 기억 스킬은 기억을 켜고 끄고, 기억 상태를 보여 주고, 기록에서 뺄 것과 원문 기록을 둘 기간을 정하고, 모든 기억을 지우고, 기억 폴더 정보를 고칩니다. 모델이나 Git은 아무것도 부르지 않습니다. 작업은 네 묶음입니다:

1. 기억 라이브러리, TASK-001\~TASK-008: 모든 파일과 잠금의 바탕, 기억 폴더 정보와 기억 설정, 실패 기록과 훅 소요 시간, 프로젝트 찾기, 지우기 처리, 원문 기록.
2. 훅인 TASK-009~TASK-017과 기억 부분·알림입니다. worker 지원은 TASK-061, 보관 기반·정책은 TASK-066과 TASK-067, 분리 실행기와 실제 실행은 TASK-068과 TASK-069입니다.

4. 출시, TASK-027\~TASK-030과 TASK-057: CI 검사, 흐름 걷기와 TASK-030의 go/no 기록. TASK-029는 제거 이력입니다.

## 이 단계가 고른 것

저마다 확인 때 바뀔 수 있습니다.

1. 다른 단계의 파일처럼, 기억 플러그인의 작업을 담는 파일 하나 `memory.md`. 이 단계의 기본 이름인 `wbs.md` 대신입니다.
2. 사람이 보는 곳은 작업마다 한 행이고 상태별 보드가 있는 Notion 데이터베이스입니다. 이 단계의 두 기본값 가운데 하나이며, 프로젝트의 기록 안에 둡니다. 원본은 보드가 아니라 이 파일입니다. 이 단계의 기본값(`human`)과는 다르고 이 프로젝트의 다른 모든 단계와는 같습니다: 작업의 상태는 그 작업을 끝내는 PR에서 여기서 먼저 바뀌고, 보드가 뒤따릅니다. 다른 기본값인 GitHub Projects는 그 기록 말고 볼 곳을 하나 더 만듭니다.
3. 담당 둘, `agent`와 `maintainer`, 그리고 날짜가 아니라 크기로 하는 추정.
4. C1은 하나하나 따로 시험할 수 있는 작은 작업으로, C2와 C3은 더 큰 작업으로 나누고, 그 큰 작업은 각 출시 단계를 시작하기 전에 다시 나눕니다.

   - C1은 이미 세션이 시작될 때마다 보관 기간 처리와 치우기를 위해 기억 작업 프로세스를 띄웁니다(SPEC-009, SPEC-013). 06단계가 계획한 대로이며, 정리는 C2에서 더해집니다.
