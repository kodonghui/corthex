# 실제 도구·세션 시작 방식·훅 재신뢰

[English](2026-11-04-memory-native-compat.md)

아래 Windows 관찰은 main `855bc6b463a4a5c57c949d1166b58db3915587c2`의 바꾸지 않은 MEMORY 제품 파일 45개로 통과했습니다. 새 CI 제어기는 같은 관찰을 Linux·macOS로 넓히며, 이 기록을 쓰는 시점에는 그 실행이 남아 있습니다. 세 운영체제 전체 케이스나 TASK-028을 완료로 바꾸는 기록은 아닙니다.

실제로 설치된 호스트 실행 파일과 실제 도구·훅을 쓰고 모델 응답만 고정된 로컬 프로토콜 서버로 줍니다. 실제 모델의 판단을 평가하는 검사는 아닙니다. 가짜 동의·키와 일회용 사용자 폴더·프로젝트·저장소만 사용합니다. 원래 계정 프로필, 실제 사용자 기록 활성화, 전역 플러그인 설치, 유료 제공자 호출은 없습니다. Codex 훅 신뢰 우회는 검토한 도구·세션 시험에만 쓰며 업데이트 시험에서는 우회하지 않습니다.

비우기·압축 시험은 기록을 끈 상태로 실제 호스트 대화 이력을 만든 뒤 가짜 프로젝트만 켜고 호스트의 실제 로컬 명령과 한국어 턴을 실행합니다. raw 시작 행을 만들거나 복사하지 않습니다. `/clear`가 기록을 끈 채 시작했던 이전 세션을 활성화 뒤 닫으면 다른 세션의 본문 없는 종료 한 행이 남을 수 있습니다. 선택한 비우기 세션에는 여전히 순서가 맞는 네 행만 있습니다. `/new`는 `startup`을 내는 것으로 관찰되어 비우기 대용으로 쓰지 않습니다. Claude는 스트리밍 CLI 로컬 명령, Unix Codex는 실제 가상 터미널의 `/clear`·`/compact`·`fork`·`/quit`를 쓰며 훅 JSON을 주입하지 않습니다. Windows 터미널 명령은 QA 터미널에 직접 입력하고 따로 판정했습니다.

보존한 Windows 종합 영수증은 `task028-native-compat-windows-v1.json`, SHA256 `81bc6e41f7d601960cdea9d9ac979b88e868d9753908db653209bca80bc7529e`입니다. 제품 파일 45개 해시와 판정 영수증 일곱 개를 묶습니다. 저장된 실제 도구 결과, 자동화한 Claude 다섯·Codex 두 시작 방식, 따로 판정한 Windows Codex 터미널 세 방식, 실제 접두사 결과, 현재 main의 재신뢰 결과입니다. 터미널 세 판정은 각각 파일이고 나머지 시작 방식은 보고서 하나에 있으므로 참조 영수증은 일곱 개입니다.

실패한 탐색과 판정 시도는 따로 남겼습니다. 첫 도구 판정기는 MAX_PATH보다 긴 Windows 폴더를 열거하지 못했습니다. 소유한 확장 경로를 열거해 저장된 Claude 성공 실행을 재실행 없이 판정했습니다. 첫 터미널 판정기는 TC-066에서 호스트 프록시 요청까지 0건이어야 한다고 잘못 요구했습니다. Codex 메타데이터 접속 시도는 차단·보존했고 raw·종료 검사 조건은 유지합니다. 제품만 따로 본 기존 TC-108 증거는 별도입니다. 앱 서버 경로의 시작 방식 탐색은 훅이 나오지 않아 인정하지 않았습니다. 실패한 탐색을 성공 실행으로 바꾸지 않았습니다.

첫 검사기 후보의 독립 리뷰에서 꼭 고칠 항목 둘과 정리 개선 하나를 찾았습니다. 재신뢰 스냅샷은 raw·header·설정과 **모든 진단 JSONL 파일**을 비교하여 시간이나 실패 행만 쓰여도 통과하지 못하게 했습니다. 시작 방식 판정은 늦은 종료 기록을 최대 6초 기다린 뒤 같은 네 행 조건을 엄격히 적용합니다. 터미널 실패 정리는 소유한 프로세스 그룹을 종료·회수하고, 증거 쓰기가 실패해도 파일 디스크립터를 닫습니다. 생성 중 터미널 크기 설정이 실패해도 정리한 뒤 원래 오류를 전파합니다. 앞의 두 보완은 통제한 회귀 시험 세 개가 수정 전 실패하고 수정 뒤 Python 3.8·3.15에서 통과했습니다. 종료 누락·경계 본문은 추가 음성 시험에서 거절합니다. 실제 Unix 자식·FD의 초기화 실패 정리 회귀는 Unix CI에서 실행할 예정이며 Windows에서는 명시적으로 건너뜁니다. 이 통제 시험을 Unix 실제 호스트 실패 관찰로 세지 않습니다. 이전 후보의 전체 시험은 미완료로 보존·중단했으며, 고친 고정 소스의 전체 검사만 게시 근거로 인정합니다.

한계도 유지합니다. 다른 `host-prompts-1` 두 갈래(`<cross-session-message`·`<teammate-message`)는 미관찰이며 작업 알림 시험으로 확인했다고 하지 않습니다. 고정한 Codex 버전의 훅 입력은 대화 파일 경로가 null이고, API 시험에서 대화 파일을 읽지 않는지 따로 확인합니다. 한 세션의 `status` 시간은 외부 100표본 성능 검사가 아닙니다. Windows·macOS p95 목표 미달과 #95·#98은 열린 상태입니다. 실제 에이전트 사용 시험, 사용자 일주일 시험, 출시 판단, 명시적인 태그 승인은 뒤에 남습니다.
