# Windows에서 실제 도구 호출이 있는 턴 확인

[English](2026-11-04-memory-tool-turn.md)

실제 설치한 Claude Code와 Codex가 고정 답변을 주는 로컬 모형 서버를 상대로 도구 호출과 한국어 최종 답변을 마쳤습니다. 기억 원문에는 같은 세션·턴의 한국어 질문·최종 답변과 시작·종료 경계가 있고, 도구에만 넣은 표식은 기억 저장소의 어떤 파일에도 없습니다. TC-043의 Windows 실제 도구 호출 부분에 대한 결과이며, 세 운영체제 전체 사례나 에이전트 걷기를 마친 것은 아닙니다.

제품은 실제 main `2fc4b871873659249e4c43c8b6139c7f5748e186`(PR #88)의 MEMORY 패키지 그대로이며, 보조 코드의 스냅샷은 `task028-v3-snapshot.json`입니다. 도구마다 임시 홈·프로젝트·플러그인 설치·기억 저장소를 썼습니다. 시험용 `on` 동의, 가짜 키와 로컬 모형 서버를 사용했습니다. 이 격리된 도구 호출 시험에서만 Codex 훅 신뢰를 우회했고, 별도의 TC-107 업데이트 관찰에서는 우회하지 않았습니다.

| 도구 | 실제 호출과 출력 | 기억 결과 |
| --- | --- | --- |
| Claude Code 2.1.310 | 실제 `Read`가 파일 이름과 내용에 `TOOL_ONLY_FIXTURE_938107`이 들어간 시험 파일을 읽었습니다. 성공한 도구 출력에 표식이 있었습니다. | 기대한 원문 네 개, 온전한 한국어, 같은 도구·세션·턴과 성공 시간 기록을 확인했습니다. 저장소에서 표식이 나온 파일은 0개입니다. |
| Codex CLI 0.164.0 | 실제 `functions.exec`가 `text("TOOL_ONLY_FIXTURE_938107");`만 실행했고, 성공한 실제 도구 결과에 표식이 있었습니다. | 기대한 원문 네 개, 온전한 한국어, 같은 도구·세션·턴과 성공 시간 기록을 확인했습니다. 저장소에서 표식이 나온 파일은 0개입니다. |

각 도구는 호출 전과 실제 도구 결과 뒤에 모형 서버로 한 번씩, 총 두 번 요청했습니다. 제어기는 실제 성공 출력을 확인한 뒤에 결과를 적격으로 판정했습니다. 모델이 도구 호출을 요청했다는 사실만으로 실행됐다고 세지 않았습니다.

Claude의 실제 transcript에도 표식이 있습니다. 177,626바이트이며 SHA256은 `9b2e3dede87fd3e15d2be38385f3a352bc07f39e0bf5ca29ac1a4ecd0523d2d5`입니다. 임시 QA 근거와 함께 비공개로 보관합니다. 처음 일반 파일 읽기는 Windows 경로가 296자로 길어 실패했으나, 소유한 시험 경로에 Windows 확장 경로 접두어를 붙여 읽는 데 성공했습니다. 운영체제 설정은 바꾸지 않았으며 실패한 읽기도 보존했습니다.

고정한 Codex 판은 `transcript_path: null`을 줍니다. 실제 도구 호출 성공과 표식 제외는 관찰했고, transcript를 읽지 않는 보호 검사는 별도의 API 시험입니다. 이 턴에서는 어느 도구도 작업·팀 알림 접두어를 내지 않았습니다. Linux/macOS의 실제 도구 턴은 남아 있으며 Windows 결과나 도구 호출 없는 세션에서 추정하지 않습니다.

적격 정본은 `task028-toolturn-v1/qualified.json`입니다. 원래 시험 코드 SHA256 `ed52d225b7ac63344560143079ed05ded52672687003a8a4371043045a24f4e1`과 결과 SHA256 `00b06b4adff305f3cbf1235e9b8604b18dd877005673b28d170acff683faa1b9`를 연결합니다. 원래 미판정 결과·실패한 transcript 읽기·후속 적격 판정은 각각 보존했습니다. 실제 제공자 호출·계정 로그인·전역 설치·실제 사용자 기억 활성화는 하지 않았습니다. 전체 사례와 진행률의 승격은 남은 근거와 검토 뒤에 합니다.
