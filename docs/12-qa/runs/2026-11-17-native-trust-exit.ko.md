# 네이티브 훅 신뢰 검토의 종료

[English](2026-11-17-native-trust-exit.md)

[PR 215의 실행 771](https://github.com/kodonghui/corthex/actions/runs/44041313478)에서 macOS 훅 작업은 이전 플러그인의 신뢰 검토 뒤 실패했습니다. 아티팩트의 터미널 기록에는 훅이 활성화되고 Hooks 패널이 열린 채로 시작 작업이 끝나 대기 상태로 돌아온 것이 보입니다. 검토는 이어서 터미널 정리를 호출했지만, Ctrl-C 입력은 취소·패널 동작이므로 정상 종료를 보장하지 않으며 프로세스는 검토에 필요한 종료 코드 0을 반환하지 못했습니다. 아티팩트는 합성 테스트 데이터이며 실제 사용자 계정이나 모델 호출이 아닙니다.

검토는 이제 Escape로 패널을 닫고 네이티브 `/quit` 명령을 보낸 뒤 프로세스 종료를 기다리고 정리합니다. 기존 종료 코드 0 검증과 신뢰·재신뢰 전 보존·캡처 검사는 모두 유지합니다. 네이티브 수명 주기 검증에서 이미 사용하는 명시적 종료 경로와 같습니다. 강제 종료나 취소를 통과로 바꾸지 않습니다.

회귀 검사는 Escape와 `/quit` 뒤에만 정상 종료하는 실제 Unix PTY 프로세스를 사용하며, Ctrl-C는 실패·취소 종료를 만듭니다. 갱신한 macOS 네이티브 훅 작업은 [실행 772](https://github.com/kodonghui/corthex/actions/runs/44054666392)에서 통과했고, HEAD `657e3f23bfac766a3fd852858df89723fdfbd95b`의 검사 39개가 모두 통과한 뒤 PR 215를 병합했습니다.

## 단위 테스트의 PTY 격리

허브 CI 설정 작업 중 [실행 44063368622](https://github.com/kodonghui/corthex/actions/runs/44063368622)의 macOS Intel Python 3.8 샤드 1이 60분 제한을 초과했습니다. 해당 작업의 로그 API는 404를 반환했고 첫 실행 로그 압축 파일에도 해당 파일이 없었습니다. 시간 초과 당시의 정확한 테스트는 아직 확인하지 못했습니다.

해당 샤드에는 실제 PTY 테스트가 있습니다. 전체 단위 테스트 프로세스에는 앞선 네트워크 테스트의 스레드가 있으며, Python은 여러 스레드가 있는 프로세스의 `forkpty`가 교착 상태를 만들 수 있다고 경고합니다. 실제 터미널 테스트 세 개는 각각 새 Python 인터프리터에서 실행합니다. 작업 프로세스는 활성 스레드가 하나인지 검사하고, 상위 프로세스는 요청한 테스트 하나가 건너뛰기 없이 실행됐는지 확인합니다. 기존 터미널·종료 상태·신뢰·프로세스 회수 assertion을 유지하며 작업 프로세스에 30초 제한을 적용합니다.

이 변경으로 공유 단위 테스트 프로세스에서 여러 스레드와 함께 fork하는 조건을 제거합니다. 과거 시간 초과의 내부 원인은 아직 검증하지 못했습니다. 레포 검사와 변경한 PR HEAD의 전체 CI로 격리 변경을 검증하며 결과는 PR에서 연결합니다.

## 인덱스 요청 기한 테스트

[실행 44099604848](https://github.com/kodonghui/corthex/actions/runs/44099604848)의 Windows Python 3.8 샤드 2는 `test_a_request_ends_before_the_runs_last_minute`에서 실패했습니다. 워커는 요청 전에 기한이 끝나 `deadline`을 올바르게 반환했지만 테스트는 요청 한 번의 타임아웃을 기대했습니다. 4초 요청 예산에 인덱스 생성과 파일 시스템 검사가 포함돼, 준비가 느리면 모델 호출 전에 예산이 끝났습니다. 전체 실행 로그 ZIP에서 해당 단언을 확인했으며 개별 작업 로그는 다운로드할 수 없었습니다.

테스트는 준비 중 테스트 시간을 고정하고 임베딩 호출부터 실제 경과 시간을 사용하도록 보완했습니다. 실제 HTTP 타임아웃과 기존 결과·진단·벡터 단언은 유지하며, 임베딩 호출이 한 번이고 실행의 마지막 1분을 예약한 기한을 받는지 추가로 검사합니다. 제품 기한과 워커 코드는 유지합니다. 변경한 HEAD의 검증 결과는 PR에 연결합니다.
