# BUG-251: 로컬 설정 덮어쓰기

상태: open. 심각도: S1. 우선순위: P1. 발견: 2026-11-28 04:26 UTC 서울 서버에서 사용자 보고.

사용자 원문: “니가 플러그인에 잘 써놨으면 될 일 아니야” (user report, 2026-11-28).

사용자는 에이전트가 profile.json과 projects.json을 다시 써서 NEXUS URL과 전송 목록, 승인 항목과 등록된 프로젝트가 사라졌다고 보고했다. 코디네이터는 에이전트 세션이 아니라 Orca 작업공간 setup 스크립트가 원인이었고 스크립트를 비웠다고 보고했다. 원인 가설은 stage 11 하네스가 외부 쓰기를 세션 시작 때 감지하지 못하고, 진입 스킬에 안전한 변경 규칙이 없었던 것이다. 재현: 임시 홈의 설정을 세션 시작에서 관찰한 뒤 두 파일의 값을 줄여 다시 쓰고 세션을 다시 시작한다. 이전 훅에는 변경 경고나 이전 복사본을 남기는 코드가 없었으며 새 회귀 테스트가 덮어쓰기를 모의한다. 피해 서버에서 직접 재현하지는 않았다.

누락 분석: 기존 설정의 변경, 백업과 보호 항목의 감소를 검증하는 회귀 테스트가 없었다. 대응은 병합·백업·보호 검사를 수행하는 명령과 외부 변경 감지이며, 다른 프로그램의 직접 쓰기를 막지는 못한다.

회귀 테스트: tests/test_profile_guard.py와 test_memory_start_hook.py (BUG-251, 이용 가능한 SPEC ID 없음). f89602d에서 스크립트 부재로 실패했다. 피해 서버의 복구와 검증은 확인되지 않았으며 병합 전까지 open을 유지한다.

## 후속: 기존 백업 때문에 첫 기준 생성 실패

상태: open. 심각도: S3. 우선순위: P1. 발견: 가드 설치 후 사용자 보고, 2026-11-28. 기존 설정 폴더에 사람이 만든 시각 백업은 있고 가드 폴더는 없을 때 `settings.py check`가 첫 기준을 저장하지 않고 보호 항목 변경을 경고했다. 감소가 확인되지 않았는데도 외부 변경 수락에 감소 승인 문구가 필요했다. 백업을 다른 곳으로 옮긴 뒤 설정 파일은 바꾸지 않고 첫 검사가 정상화되었다는 코디네이터 보고이며, 해당 기기에서 독립 검증하지는 않았다.

재현: 유효한 프로필과 프로젝트 설정 옆에 가드 도입 전 백업을 두고 가드 폴더 없이 `settings.py check`를 실행한다. 원인 가설: stage 11 구현이 비슷한 이름의 백업을 모두 기존 기준의 증거로 취급한다. 누락 분석: 손상된 기준은 검사했지만 관련 없는 백업이 있는 첫 관찰은 검사하지 않았다. 프로필 문서를 고치고 가드의 백업 형식과 기록 표식을 구분하며 가드 기록이 있으면 경고를 유지한다. 이전 기준이 손상되어 내용을 알 수 없을 때의 별도 감소 승인 요구는 보수적으로 유지하되 실제 감소가 확인됐다고 표현하지 않는다.

회귀 테스트: `tests/test_profile_guard.py` (BUG-251 후속, 승인된 SPEC ID 없음), `0076727`에서 실패 확인. Stopped by: 코드 구조가 가드 기록과 관련 없는 백업 이름을 구분하며 첫 사용과 기록 유실을 회귀 테스트로 검사한다. 정적 타입이나 린트는 파일 시스템의 과거 상태를 알 수 없다.
