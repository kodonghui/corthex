# BUG-251: Local settings overwritten

Status: open. Severity: S1. Priority: P1. Found in: user report, 2026-11-28 04:26 UTC, Seoul server.

User’s words: “니가 플러그인에 잘 써놨으면 될 일 아니야” (user report, 2026-11-28).

The user reported that an agent rewrote profile.json and projects.json, losing the NEXUS URL and push entries, approval categories and registered projects. The coordinator reported that the Orca workspace setup script, not an agent session, overwrote both files on each workspace creation; the script has since been cleared. Cause hypothesis: external writes have no session-start change detection, and the entry skill omits update and preservation rules (stage 11 harness). Reproduction on a disposable home: observe populated settings in a session start, overwrite both files with reduced settings, and start another session; the prior hook has no code to produce a change warning or keep a prior copy (source inspection); the new regression simulates that overwrite. This is a local simulation, not verification on the affected server.

Escape: no regression exercised updates to existing local settings; add cases for preservation, backups and protected reductions. Proposed guard: a constrained update API with protected-field checks and backups plus external-change detection; neither instructions nor the API can prevent an external setup script from writing directly.

Regression test: tests/test_profile_guard.py and test_memory_start_hook.py (BUG-251; no SPEC ID available); the guard tests failed on f89602d before the script existed. Production restoration and verification on the affected server remain unconfirmed; status stays open until merged.
