# 첫 프로젝트

[English](first-project.md)

핵심 플러그인 설치, 프로필 설정, 연습 프로젝트 등록, 요구사항 하나 검토, 진행 기록 찾기까지 따라갑니다. 짧은 세션 하나를 잡으세요. Git과 이미 로그인하여 사용할 수 있는 Claude Code 또는 Codex가 필요합니다. 호스트 로그인·계정 과금은 이 안내의 범위 밖이며 인증 정보는 현재 기기에 둡니다. 이 경로에서 CORTHEX의 유료 서비스나 백그라운드 기록을 추가하지 않습니다.

비어 있는 연습 폴더를 사용하세요. 프로필이나 프로젝트 목록이 이미 있으면 기존 항목을 보존하고 명시적으로 고른 값만 바꾸도록 요청하세요. 예제 파일로 덮어쓰지 않습니다.

## 1. 설치하고 새 세션 열기

Windows의 PowerShell 또는 macOS의 bash/zsh에서 쓰는 호스트의 두 명령을 실행하세요.

| Claude Code | Codex |
| --- | --- |
| `claude plugin marketplace add kodonghui/corthex` | `codex plugin marketplace add kodonghui/corthex` |
| `claude plugin install corthex@corthex` | `codex plugin add corthex@corthex` |

각 명령이 성공해야 합니다. 설치 오류가 나면 멈추고 비밀을 제외한 오류와 호스트 버전(`claude --version` 또는 `codex --version`)을 남기세요. 마켓플레이스가 이미 등록돼 있으면 삭제하지 말고 호스트의 마켓플레이스 갱신 명령을 사용하세요. 여기서는 `corthex`만 설치합니다. MEMORY와 NEXUS는 나중에 선택할 수 있습니다.

원하는 상위 폴더에서 다음을 실행하세요. 두 셸에서 같습니다.

```text
mkdir corthex-practice
cd corthex-practice
git init
```

폴더가 이미 있으면 다른 연습 이름을 고르세요. 그곳에서 `claude` 또는 `codex`로 **새** 세션을 여세요. Claude Code에서는 `/corthex:corthex`를 실행하세요. Codex에서는 “설치된 corthex 진입 스킬을 사용하세요. 쓰기 전에 불러온 스킬 파일 위치를 보여 주고 프로필·프로젝트 참조 문서를 읽어 주세요”라고 요청하세요.

예상 결과는 설치된 플러그인에서 진입 스킬을 찾아 현재 폴더와 기존 프로필·목록을 확인하는 것입니다. 못 찾으면 멈추고 호스트의 플러그인 목록에서 설치를 확인한 뒤 다시 시작하세요. 발견 문제를 우회하려고 전역 지침 파일을 만들거나 훅을 켜지 않습니다.

## 2. 프로필과 프로젝트를 고르고 검토하기

새 세션에 다음을 보내세요.

> `corthex-practice`라는 연습 프로젝트입니다. 한국어 존댓말을 사용하고 사용자님으로 불러 주세요. 기록은 Git의 `docs/records/`에 둡니다. 제가 변경을 고르지 않은 기존 프로필·프로젝트 목록 값은 보존하세요. 쓰기 전에 프로필·프로젝트 설정 제안을 보여 주세요. 02단계는 기본 Notion 데이터베이스 대신 저장소 Markdown으로 보겠습니다. `human: git`, `source: docs/02-prd/requirements.md`, `truth: source`를 사용하세요. 이 선택을 제 원문·현재 세션·실제 날짜와 시각으로 결정 기록에 남기세요. 02단계부터 시작하므로 빠진 01단계 입력을 나열하고, 이 연습의 작은 용어·문맥 하나를 제안한 뒤 승인받아 사용하세요. 배포나 외부 메시지는 보내지 않습니다.

제안한 경로와 JSON을 검토하세요. 의도에 맞으면 적용과 연습 문맥 사용을 승인하세요. 바꾸고 싶지 않은 값까지 승인하지 마세요. 프로필은 `~/.corthex/profile.json`(Windows는 `%USERPROFILE%\.corthex\profile.json`), 기기별 목록은 `~/.corthex/projects.json`, 저장소 설정은 `.corthex/project.json`에 있습니다. 계정 인증 정보는 넣지 않습니다.

예상 결과는 연습 경로의 목록 항목 하나, `records.kind: git`와 `records.location: docs/records/`, 그리고 `02-prd`의 선택한 `human`·`source`·`truth`와 결정 기록을 가리키는 `note`입니다. 다른 단계의 산출물을 만들어 채울 필요는 없습니다.

## 3. 요구사항 하나를 쓰고 검토하기

다음을 보내세요.

> 02단계에서 Must 기능 요구사항 하나를 초안으로 쓰세요. 메모를 추가하면 연습 앱이 내용을 저장합니다. REQ-001과 승인한 연습 문맥을 사용하고, 이 요청을 출처로 적으세요. 범위는 이 동작 하나입니다. 범위를 고정하기 전에 요구사항과 열린 질문을 보여 주세요.

예상 결과는 `docs/02-prd/requirements.md`에 EARS 문장 하나로 쓴 REQ-001과 유형·우선순위·문맥·출처·상태가 있는 것입니다. 이 연습에서 “저장”이 뜻하는 바를 검토하고 필요한 질문에 답하세요. 만족하면 범위를 명시적으로 승인하세요. 파일이 있다고 체크포인트를 통과한 것은 아닙니다.

## 4. 결과와 기록 찾기

범위 결정과 진행을 기록하고 현재 단계·확인한 것·다음 행동을 보고하도록 요청하세요. 연습 저장소의 터미널에서 실행하세요.

```text
git status --short
git diff --check
```

추적하지 않은 새 파일은 직접 읽으세요. `git diff`에는 그 내용이 나오지 않습니다. `.corthex/project.json`, 요구사항, `docs/records/` 아래의 결정 기록과 진행 기록을 찾으세요. 진행 기록에는 실제 확인한 파일과 앱 구현·배포를 하지 않았다는 점이 있어야 합니다. 연습 폴더를 사용할지 지울지 결정할 때까지 보존하세요.

설치된 스킬, 프로필과 목록, REQ-001, 그 승인과 진행 기록의 위치를 찾을 수 있으면 이 경로를 마친 것입니다. 흐름을 더 만들고 싶으면 03단계로 이어가세요. 에이전트·명령 재현은 실행 경로의 증거입니다. 처음 읽는 사람이 배웠는지는 실제 독자가 사용하는 모습을 관찰해야 알 수 있습니다.
