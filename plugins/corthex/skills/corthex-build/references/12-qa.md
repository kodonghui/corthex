# Stage 12 · QA

| Slot | This stage |
| --- | --- |
| Inputs | User flows (FL), the acceptance criteria in the functional spec (SPEC) and the screen states (SCR) |
| Outputs | `test-plan.md`, by default `docs/12-qa/test-plan.md`, with TC IDs mapped to FL and SPEC; automated end-to-end tests where they pay off, for example with Playwright; bug reports with BUG IDs |
| Human view | A QA checklist or the bug tracker, as set in `human` |
| Sync | Test runs update the plan. Each bug links the test case, the screen and the spec row it breaks |
| Human checkpoints | The release decision: go or no-go |
| Trace IDs | TC-001…, BUG-001… |

## Steps

1. Write test cases from the flows and the acceptance criteria, not from the code.
2. Automate the cases that run often or guard money, data or access; keep the rest as manual checks.
3. Run the plan, record each result with the build or commit it ran against, and file bugs.

## Checks

- Every flow's main path and main failure paths have a test case.
- Every acceptance criterion has a test case.
- Every bug has steps, expected and actual results, the environment and evidence.
